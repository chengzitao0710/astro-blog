# 2026-08-07 工作日志

## 图片加载失败回退修复

### 问题
1. Cloudflare 图床图片在浏览器中可能加载失败
2. about.astro 和 ArticleCard.astro 的 onerror 使用模板字符串内嵌 `&quot;`，被 Astro 二次转义为 `&amp;quot;`，导致回退 HTML 无效
3. about.astro 联系卡片的 GitHub 头像回退图标默认可见（`.contact-icon-fallback` 缺少 `display:none`）

### 修复方案
将所有图片回退从 `outerHTML` 替换方式改为**兄弟元素方式**：同时渲染 img 和隐藏的回退元素，onerror 仅切换 display 属性。

### 修改的文件
- `src/pages/index.astro` — 首页 Hero 头像：img + 隐藏 span 回退
- `src/pages/about.astro` — 关于页 Hero 头像：img + 隐藏 div 回退；联系卡片：添加 `.contact-icon-fallback { display:none }` 和 `.contact-avatar-wrap` 容器样式
- `src/components/ArticleCard.astro` — 文章卡片封面：img + 隐藏 div 回退
- `src/components/Header.astro` — 导航栏 Logo（静态字符串，`&quot;` 未被二次转义，无需修改）
- `src/pages/posts/[slug].astro` — 文章详情页封面（仅隐藏父容器，无需修改）

### 额外改进
- 所有外部图片添加 `referrerpolicy="no-referrer"` 防止 Referer 被拦截

### 关键经验
**Astro 模板字符串属性中的 `&` 会被 HTML 转义为 `&amp;`**，所以 `&quot;` 会变成 `&amp;quot;`。静态字符串属性不受影响。解决方案：避免在模板字符串 onerror 中构造含属性的 HTML，改用兄弟元素 + display 切换。

## Giscus 深色主题页面导航后不跟随修复

### 问题
`config.ts` 中 Giscus `data-theme="preferred_color_scheme"` 跟随系统而非用户手动切换。页面导航（MPA 全量刷新）后，`trySync` 的 `postMessage` 在 Giscus 内部未就绪时发出，评论区始终显示错误主题。

### 修复方案
重写 `Giscus.astro`：用隐藏 `<span>` 承载配置（dataset），`is:inline` 同步脚本在 HTML 解析阶段读取 `<html data-theme>` 并动态创建 Giscus `<script>`，`data-theme` 直接设为 `dark` 或 `light`。后续手动切换仍通过 MutationObserver + postMessage 同步。

- 删除 `trySync` 重试循环（不再需要）
- 保留 MutationObserver 监听 `data-theme` 变化

## 修复 ClientRouter 导致的三个 bug（22:32）

**根因**：`astro:transitions` ClientRouter 导航时，普通 `<script>` 块（Vite 打包）存在事件监听器累积、DOM 查询时机不对、Observer 泄漏等问题。

**修复**：
1. ThemeToggle.astro：`<script>` → `<script is:inline>` + `cloneNode(true).replaceChild` 替换节点以剥离旧事件监听器，再绑定新的 click
2. Giscus.astro：两个 `<script>`（一个 is:inline 创建 Giscus、一个普通 script 做 MutationObserver）合并为单一 `<script is:inline>`；新增清理旧 iframe/旧 Giscus script 的逻辑；MutationObserver 内联在同一脚本中
3. [slug].astro：整个大脚本块 `<script>` → `<script is:inline>`；签名 IntersectionObserver 外包 `requestAnimationFrame` + 若元素已在视口则直接触发 `visible`，不再依赖 observer 回调

## ClientRouter 兼容性彻底修复（22:45）

## 修复返回顶部按钮消失（22:54）

**问题**：`[slug].astro` 中返回顶部按钮的 JS 仍使用 `cloneNode` 反模式。`fn` 闭包捕获的 `btn` 在 `cloneNode` + `replaceChild` 后已从 DOM 移除，`classList.add('float-visible')` 操作的是已脱离文档的旧节点，按钮始终不可见。

**修复**：去掉 `cloneNode` + `replaceChild`，scroll 函数和 click 监听器直接操作同一个 DOM 元素。`cleanupArticle()` 在每次 `astro:page-load` 时已正确清除 scroll 监听器，无需通过 clone 来防止重复绑定。

**关键经验**：`cloneNode` 反模式与之前的 ThemeToggle 完全一致。在有 `astro:page-load` + cleanup 机制的情况下，`cloneNode` 不仅多余而且有害——它会让闭包中的引用指向已移除的 DOM 元素。
