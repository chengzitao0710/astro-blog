## 修复按钮位置、底部遮挡、主题切换（10:22）

### 问题
1. 返回顶部按钮太贴右下角（`right: 8px; bottom: 24px`）
2. 页面滚到底部时按钮被 footer 遮挡，点击无效
3. 主题切换按钮点击无反应

### 根因分析

**底部遮挡**：`.layout-main` 和 `.layout-footer` 都是 `z-index: 1`，两者在同级 stacking context 中，footer 因 DOM 顺序靠后而画在 main 之上。浮按钮虽然在 `.layout-main` 内部 `z-index: 99`，但被整个 main 的层级限制，footer 覆盖了它。

**主题切换**：`is:inline` 脚本中 `document.getElementById('theme-toggle')` 在 ClientRouter 某些导航场景下可能返回 null（时序问题）。

### 修复
1. **`[slug].astro`**：`.float-btn-group` 的 `right` 8px→24px，`bottom` 24px→48px，`z-index` 15→99
2. **`BaseLayout.astro`**：`.layout-footer` z-index 1→0，确保浮按钮所在的 `.layout-main`（z-index:1）始终画在 footer 之上
3. **`ThemeToggle.astro`**：`is:inline` 脚本加 IIFE 包裹、`__themeToggleBound` 防重复绑定、`requestAnimationFrame` 自旋重试确保 DOM 就绪后绑定

### 关键经验
- `position: fixed` 元素的 z-index 受其包含块（nearest ancestor that creates stacking context）的 z-index 限制。即使子元素 z-index: 99999，父级 z-index 低时仍会被同级其他元素覆盖。
- `is:inline` 脚本在 ClientRouter + Astro 组件嵌套场景下，DOM 就绪时机不可靠，需要自旋重试 + guard 双重保险。

## 主题切换再次修复（10:28）

### 问题
上一次修复（10:22）加了 `__themeToggleBound` + `rAF` 自旋重试，但主题切换仍然不工作。

### 根因
`__themeToggleBound` 全局 flag：首次加载时脚本执行、flag 设 `true` 并绑定事件。ClientRouter 导航后整个 DOM（包括 `<button#theme-toggle>`）被替换为新元素，但 `is:inline` 脚本再次执行时 `__themeToggleBound === true`，直接 return，跳过了给新按钮绑定事件。

### 修复
**放弃 `is:inline` 方案，改用事件委托**：
1. `ThemeToggle.astro` — 删除所有 `<script is:inline>` 代码
2. `BaseLayout.astro` — 在 `</body>` 前新增事件委托脚本：
```js
document.body.addEventListener('click', (e) => {
  const btn = e.target.closest('#theme-toggle');
  if (!btn) return;
  // toggle logic...
});
```
委托监听器只注册一次，不依赖按钮是否被替换。只要点击目标能匹配 `#theme-toggle`，就能响应。

### 关键经验
**`is:inline` + guard flag 模式在 ClientRouter 下根本不可行**。guard flag 阻止了 DOM 替换后的重新绑定，这是它设计上的结构性缺陷。事件委托才是唯一可靠的方案。

## 修复 View Transitions 导航后主题丢失（10:53）

### 问题
点击文章链接（View Transitions 导航）后，暗色模式丢失，页面切回浅色。用户报告"点击文章为什么会切换主题"。

### 根因
Astro View Transitions 在 DOM swap 阶段会用新页面的服务端 HTML 属性更新 `<html>` 元素。服务端渲染的 `<html lang="zh-CN">` 不含 `data-theme`，所以 swap 后 JS 设置的 `data-theme="dark"` 被移除。

虽然 `<head>` 中的 `is:inline` 脚本带有 `data-astro-rerun`，但脚本可能在 `<html>` 属性同步**之前**执行——先设了 `data-theme`，随后被 swap 的属性覆盖移除。

### 修复
**`BaseLayout.astro`** — 在底部 `<script>` 块中新增 `astro:after-swap` 事件监听器：
```js
function restoreTheme() {
  const saved = localStorage.getItem('theme');
  const dark = saved ? saved === 'dark' : window.matchMedia('(prefers-color-scheme: dark)').matches;
  if (dark) document.documentElement.setAttribute('data-theme', 'dark');
  else document.documentElement.removeAttribute('data-theme');
}
document.addEventListener('astro:after-swap', restoreTheme);
```

`astro:after-swap` 在 DOM swap **全部完成后**、过渡动画播放前触发，此时恢复主题不会闪烁。

同时将事件委托从 `document.body` 改为 `document`（body 在 swap 中被替换，document 不会），并给 `is:inline` 脚本添加 `data-astro-rerun` + 显式处理浅色模式（`removeAttribute`）。

### 关键经验
- Astro View Transitions swap 会用新页面 `<html>` 属性覆盖现有属性，JS 动态设置的 `data-theme` 会丢失
- `data-astro-rerun` 不能保证在属性同步之后执行，时序不可靠
- `astro:after-swap` 是 View Transitions 导航后恢复 DOM 状态的可靠时机（swap 完成后、动画前）
- 事件委托应绑在 `document` 而非 `document.body`——body 在 swap 中被替换，监听器会丢失

## About 页面内容不显示修复（14:00）

### 问题
点击导航到 About 页面时，页面内容有时不显示（空白）。

### 根因
`about.astro` 的入场动画脚本用普通 `<script>` 标签，View Transitions 导航时不重新执行。`[data-reveal]` 元素 CSS 初始状态为 `opacity: 0`，但 IntersectionObserver 从未创建，元素永远不可见。其他页面（search、archive、posts）都正确使用了 `astro:page-load` 事件。

### 修复
将脚本包裹在 `document.addEventListener('astro:page-load', ...)` 中，确保每次导航后重新执行。额外优化：视口内元素直接添加 `revealed` 类（不等待 IntersectionObserver 回调），避免导航后首屏内容闪现。
