## 主题切换按钮修复（10:25）

### 问题
主题切换按钮点击无反应。

### 根因
`ThemeToggle.astro` 中 `is:inline` 脚本 + `window.__themeToggleBound` guard flag：首次加载绑定成功并设 flag=true，ClientRouter 导航后 DOM 被替换为新按钮，但脚本因 flag 跳过不重新绑定。

### 修复
放弃 `is:inline`，改用事件委托：
- `ThemeToggle.astro` — 删除所有 `<script is:inline>` 代码
- `BaseLayout.astro` — 在 `</body>` 前新增 `document.body.addEventListener('click', ...)` 委托监听
- 委托监听器只注册一次，不依赖按钮 DOM 是否存在

### 关键经验
`is:inline` + guard flag 模式在 ClientRouter 下根本不可行。事件委托才是唯一可靠方案。

## iPhone SE 适配五轮（11:43）— 找到根因

### 根因
用户预览 iframe 的宽度很可能在 375px–640px 之间（workbuddy preview 的 iframe 视口不是精确的 375px），所以 `@media (max-width: 375px)` 的规则**根本没触发**。这就是为什么之前所有改都没生效——代码没执行，不是 CSS 写错或缓存问题。

### 修复
把 grid + block 布局的核心规则从 `@media (max-width: 375px)` 移到 `@media (max-width: 640px)`：
- `@media (max-width: 640px)`：hero-badges 用 grid 3 列、feed-list 改 block 布局、隐藏时间线——覆盖所有窄视口
- `@media (max-width: 375px)`：仅保留更紧凑的 padding 和字号——继续覆盖超窄屏

### 关键经验
- **响应式断点要按"区间"覆盖**：不要只适配某个具体设备宽度，要让中间区间（如 400-600px）也能工作
- **`is:global` + `!important` + 合理断点 = 万无一失**：scope 隔离不能解决"断点没触发"这种根本问题

### 问题
三轮修改后用户仍截图显示旧版布局：GitH 被截、feed 日期被换行、时间线圆点还在。dist 中 CSS 包含正确规则（已 grep 验证），但用户视图显旧版——疑似 workbuddy iframe 缓存或 scoped CSS 的 `data-astro-cid-*` 选择器匹配问题。

1. **`index.astro` `<style>` 改为 `<style is:global>`** —— 规则不再带 `data-astro-cid-lcdefpme` 限定符，无 scope 依赖

3. **重启新 preview 服务 4324**（旧 4321/4322/4323 仍占用）

### 关键经验
- **scoped CSS 在 iPhone SE 适配调试中容易踩坑**：Astro 默认 `<style>` 加 `[data-astro-cid-*]`，若 BaseLayout 或其他文件链有冲突，scoping 匹配不上规则会静默失效

## 部分文章缺少目录和评论区修复（18:20）

### 问题
用户报告"有一些文章没有目录和评论区"。

### 根因
1. **TOC 侧边栏 CSS 断点过大**：`@media (max-width: 1280px)` 隐藏了 `#layout-sidebar`，但移动端浮动按钮只在 `≤1024px` 显示。1025px-1280px 屏幕宽度的用户（常见笔记本）完全看不到 TOC。
2. **Giscus 脚本 View Transitions 竞态**：`is:inline` 脚本无 `data-astro-rerun`，从非文章页导航到文章页时脚本可能不执行；即使执行，`astro:page-load` 可能在监听器注册前已触发，导致 `loadGiscus()` 未被调用。
3. **文章页脚本同样问题**：`[slug].astro` 的初始化脚本无 `data-astro-rerun`，首次导航到文章页时可能不执行。

### 修复
1. **CSS 断点**：`@media (max-width: 1280px)` → `@media (max-width: 1024px)`，与移动端浮动按钮断点对齐
2. **Giscus 脚本**：添加 `data-astro-rerun`，分离「注册监听器（只一次）」和「调用 loadGiscus（每次执行）」，`giscusReady` 改为 `window.__giscusReady` 避免闭包问题
3. **文章页脚本**：添加 `data-astro-rerun` + IIFE 包裹 + `__articleSetup` guard 防止重复注册监听器，每次执行直接调用 `cleanupArticle() + initArticlePage()`

### 关键经验
- `is:inline` + View Transitions：脚本只在首次出现时执行，后续导航靠 `astro:page-load` 监听器。但如果 `astro:page-load` 在监听器注册前已触发，初始化会丢失。解法：`data-astro-rerun` + guard 分离注册和执行 + 每次直接调用初始化函数
- CSS 媒体查询断点要对齐：桌面隐藏侧边栏的断点必须 ≤ 移动端显示浮动按钮的断点，否则中间区间无 TOC
